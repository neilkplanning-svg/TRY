# גחלת — אתר הדגמה: Pages CMS + Google Sheets

אתר מסעדה **בדיוני לגמרי** (שמות, אנשים, יקבים ומספרי טלפון מומצאים) שנבנה כדי לבדוק בפועל את שתי השיטות לניהול תוכן ע"י לקוח באתר סטטי, באותו אתר — כל שיטה אחראית על אזורים אחרים.

| מה | איפה זה מנוהל | למה דווקא שם |
|---|---|---|
| טקסטים, תמונות, צוות, אירועים, גלריה, ביקורות, שאלות נפוצות, פס הודעה, פרטי העסק | **Pages CMS** → `content/*.json` | תוכן "שיווקי" עם תמונות, שמשתנה כמה פעמים בחודש |
| תפריט ומחירים, מנות היום, שעות פתיחה, תפריט יינות | **Google Sheets** → 4 לשוניות | נתונים טבלאיים שמשתנים כל יום, מהטלפון, ע"י הצוות במטבח |

> טיפ לבדיקה: בכל עמוד אפשר להוסיף `?sources=1` לכתובת (או ללחוץ "הצגת מקורות התוכן" בתחתית), וכל אזור יסומן — **כחול** = Pages CMS, **ירוק** = Google Sheets.

## מבנה האתר

```
index.html        דף בית: באנר, מנות היום (Sheets), פילוסופיה, מנות דגל, מספרים, ביקורות (קרוסלה),
                  אירועים קרובים, שעות + "פתוח עכשיו" (Sheets), גלריה, קריאה לפעולה
menu.html         תפריט מלא מ-Sheets: חיפוש, סינון (טבעוני/ללא גלוטן/חריף…), ניווט קטגוריות דביק,
                  "אזל להיום", תפריט יינות, הדפסה נקייה
about.html        סיפור (rich text), ציטוט, ציר זמן, ערכים, צוות
events.html       אירועים קרובים (עוברים אוטומטית ל"אירועים שהיו" לפי תאריך), חבילות לאירועים פרטיים
gallery.html      גלריה עם סינון קטגוריות ו-lightbox (מקלדת + החלקה בנייד)
contact.html      טופס הזמנה ששולח וואטסאפ/מייל, שעות הגעה לפי היום שנבחר (מ-Sheets), מפה, שאלות נפוצות
accessibility.html  תבנית הצהרת נגישות

.pages.yml        הגדרות ממשק הניהול של Pages CMS (מה הלקוח רואה ויכול לערוך)
content/*.json    התוכן שהלקוח עורך דרך Pages CMS
data/sheets/*.csv גיבוי מקומי + תבנית לייבוא לגוגל שיטס
js/config.js      חיבור לגיליון (sheetId)
js/lib/           cms.js · sheets.js (כולל שרשרת גיבוי) · layout.js · hours.js · dom.js · csv.js
js/pages/         קוד לכל עמוד
images/uploads/   תמונות (כרגע איורי SVG זמניים — הלקוח מחליף דרך ה-CMS)
```

אין build, אין npm, אין framework — HTML/CSS/JS נקי שעולה כמו שהוא ל-GitHub Pages.

## הרצה מקומית

```bash
python3 -m http.server 8000
```

ואז לפתוח http://localhost:8000 (חייבים שרת — `fetch` לא עובד מ-`file://`).

## שלב 1 — פרסום ב-GitHub Pages

1. בריפו: **Settings → Pages → Build and deployment → Deploy from a branch**, לבחור את הענף ותיקיית `/ (root)`.
2. אחרי דקה-שתיים האתר יעלה ב-`https://<user>.github.io/<repo>/`.
3. הנתיבים באתר יחסיים, אז זה עובד גם בתת-תיקייה וגם על דומיין פרטי.

> ⚠️ GitHub Pages בריפו **פרטי** דורש מנוי GitHub Pro. לריפו פרטי בחינם — ראו "Cloudflare Pages" בהמלצות למטה.

## שלב 2 — חיבור Pages CMS (אפשרות 1)

1. נכנסים ל-https://app.pagescms.org ומתחברים עם GitHub.
2. מאשרים את ה-GitHub App של Pages CMS **רק על הריפו הזה** (לא "All repositories").
3. בוחרים את הריפו והענף — הממשק נבנה אוטומטית מ-`.pages.yml`.
4. להזמנת לקוח: **Settings → Collaborators** בתוך Pages CMS → כתובת מייל. הלקוח מקבל קישור התחברות במייל, ולא צריך חשבון GitHub.
5. כל לחיצה על **Save** = commit לריפו → GitHub Pages מפרסם מחדש תוך ~1–2 דקות.

**מה לבדוק בפועל:** להחליף תמונה בבאנר הראשי, להוסיף אירוע עם תאריך עבר (צריך לעבור ל"אירועים שהיו"), לכבות את פס ההודעה, להוסיף איש צוות בלי תמונה (יוצגו ראשי תיבות), להדביק טקסט עם `<script>` בשדה rich-text (יסונן).

## שלב 3 — חיבור Google Sheets (אפשרות 2)

1. יוצרים גיליון חדש עם 4 לשוניות בשמות המדויקים: `תפריט`, `מנות היום`, `שעות פתיחה`, `יינות`.
2. בכל לשונית: **קובץ → ייבוא → העלאה** של הקובץ המתאים מ-`data/sheets/` → "החלפת הגיליון הנוכחי".
3. **שיתוף → כל מי שיש לו את הקישור → צופה.**
4. מעתיקים את ה-ID מהכתובת (`/spreadsheets/d/<ID>/edit`) ומדביקים ב-`js/config.js` בשדה `sheetId`.
5. Commit — ומעכשיו כל שינוי בגיליון מופיע באתר ברענון הבא.

**כללים ללקוח:**
- לא לשנות את שורת הכותרות (מותר עברית או אנגלית — הקוד מזהה את שתיהן).
- עמודת **מחיר** — מספרים בלבד (בלי ₪). גוגל מנחש סוג עמודה, ועמודה מעורבת עלולה להחזיר תאים ריקים.
- **זמין** = `FALSE` מציג "אזל להיום" עם קו חוצה. **פעיל** = `FALSE` מסתיר מנת יום.
- **תגיות**, מופרדות בפסיק: טבעוני, צמחוני, ללא גלוטן, חריף, המלצת השף, חדש.
- **שעות**: עמודות פתיחה/סגירה ריקות = סגור. סגירה אחרי חצות (`00:30`) נתמכת.

**מה לבדוק בפועל:** לשנות מחיר מהטלפון ולרענן; לסמן מנה כ-FALSE; לבטל את השיתוף של הגיליון (האתר צריך לעבור לגיבוי ולהציג זאת למעלה בעמוד התפריט); לשנות שם של כותרת עמודה (תופיע שגיאה ב-console והאתר ימשיך לעבוד מהגיבוי).

### שרשרת הגיבוי של Sheets

```
Google (חי) ──נכשל──▶ עותק אחרון שנשמר בדפדפן ──אין──▶ data/sheets/*.csv מהריפו
```

בעמוד התפריט מופיעה נקודה צבעונית שמראה מאיפה הגיעו הנתונים: ירוק = חי, צהוב = עותק שמור, כחול = קובץ מקומי.

## הערות לגרסה ללקוח אמיתי

- **תמונות:** Pages CMS לא מכווץ תמונות. תמונה של 6MB מהטלפון תעלה כמו שהיא. כדאי להוסיף GitHub Action לכיווץ (למשל `calibreapp/image-actions`) או להגיש דרך Cloudflare.
- **SEO:** התוכן נטען ב-JavaScript. גוגל יודע לרנדר JS, אבל לאט וחלקית. לאתר שבו SEO קריטי, עדיף שלב build (11ty/Astro) שמייצר HTML מה-JSON, או Action שמושך את הגיליון לריפו פעם בשעה.
- **נגישות:** בישראל אתר של עסק חייב לעמוד בתקן 5568 ולכלול הצהרת נגישות. האתר בנוי עם בסיס טוב (סמנטיקה, מקלדת, ניגודיות, `prefers-reduced-motion`), אבל לפני מסירה צריך בדיקה מלאה.
- **וואטסאפ בטופס:** המספר ב-`settings.json` בדיוני. להחליף במספר אמיתי בפורמט `9725XXXXXXXX`.
